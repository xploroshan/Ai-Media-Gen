# DECISIONS.md — ambiguity resolutions (per CLAUDE.md)

Choices made where SPEC.md is ambiguous or silent; simplest option consistent with its architecture.

1. **Workspace root** — SPEC §2 shows the monorepo root as `reelforge/`, but the repo is `Ai-Media-Gen`. The repo root IS the monorepo root; the root package is named `reelforge`. No nested directory.
2. **Worker Python version** — Worker Docker image is `python:3.12-slim` per SPEC §2. The dev host has Python 3.11; the container is the source of truth for pytest (`docker compose exec worker pytest`), host runs are best-effort.
3. **CI semantics** — `.github/workflows/ci.yml` is authored per SPEC §2 (lint → typecheck → unit → e2e, StubProvider only). Phase gates are verified by running the identical suite in the dev environment; GitHub-hosted runner execution depends on the repo's Actions settings which are outside the build's control.
4. **pgvector** — CLIP embeddings stored as JSONB (SPEC §4 allows pgvector "if extension available, else JSONB"). v1 does no ANN search, so JSONB is the simplest guaranteed path. Swap = one migration + write path change.
5. **E2E OTP access** — SPEC §3 says dev mode prints the OTP to console. Playwright cannot reliably scrape the dev-server console, so a dev/test-only route `GET /api/dev/last-otp?email=` (404 in production builds, enabled only when `RESEND_API_KEY` is unset) exposes the last OTP issued for an email. Production behavior unchanged.
6. **H.264 playback in e2e** — Playwright's open-source Chromium build has no H.264/AAC decoders (`canPlayType` returns ""), so `<video>` playback of rendered MP4s cannot run in the test browser (works in real Chrome/Safari/Firefox). The P2 e2e asserts real playback when the browser supports H.264 and otherwise asserts player wiring (src + bytes served) — the rendered file is always verified via ffprobe (duration/dims/streams) regardless.
7. **`Job.runAfter` column** — SPEC §5.3 requires exponential retry delays (30 s, 2 min) but the §4 `Job` model has no scheduled-time field. Added `runAfter DateTime?` (`run_after`); the claim query skips jobs whose `run_after` is in the future. Minimal addition needed to implement the specified semantics without abusing `lockedAt`.
8. **fal slug verification** — SPEC §8.2 asks that the placeholder slugs be verified against the live fal catalog at build time. Attempted at P5: fal.ai answers HTTP 429 to every request from this build environment (catalog and per-model pages), so live verification was impossible. The spec's placeholder slugs are seeded as-is. Mitigations already in the design: slugs live only in the `gen_models` table (admin CRUD at `/api/admin/models`), `FalProvider` activates only when `FAL_KEY` is set, and the live smoke test (`RUN_LIVE_AI=1` + `FAL_KEY`, never in CI) surfaces a stale slug immediately. **Before production use: run the live smoke and correct slugs via the admin panel.**
9. **Speech audio in the final mix** — SPEC §6.6.6 ducks music "under speech" but lists only music in the audio chain. Interpreted as: video clips whose asset has a transcript contribute their source audio to the mix (aligned to the timeline through the trim/speed), and music is ducked by `duckUnderSpeechDb` inside merged word windows (from those transcripts + enabled captions). Clips without transcripts stay silent under the music, which is the expected beat-synced-reel behavior.
10. **Transform is present but render-inert in v1** — §5.1 defines `transform {scale,x,y,rotate}` on video clips and §7 lists it in the properties panel. The renderer's fit strategy (§6.6.1 scale-to-fill + crop) fully determines framing, and applying user transforms on top of zoompan/xfade chains is out of v1's scope. The field round-trips through editor and API (so specs stay §5.1-valid) but does not alter the filtergraph. The properties panel exposes what the renderer honors (speed, transitions, kenBurns).
11. **PATCH render flag instead of optimistic versioning** — §5.4's `PATCH /projects/:id` saves the spec; re-render is opt-in via `{render:true}` (autosave saves without rendering; the editor's "Preview render" sends it). Concurrent-writer safety comes from rejecting PATCH while an autoedit job is queued/running (409 `autoedit_in_progress`) and from the worker's seed-guard: the autoedit result only lands if `projects.seed` still equals the payload seed. A full `version`/ETag scheme was judged out of v1 scope for a single-user editor.
12. **taken_at timezone normalization** — EXIF `DateTimeOriginal` is timezone-naive local time; video `creation_time` is UTC (`Z`). Mixing aware and naive datetimes breaks clustering math, so video creation times are converted to **naive UTC** before storage and EXIF stays naive as-is. The 4-hour event gap (§6.2) dwarfs typical offset error for same-shoot media from one device.
13. **GenProvider is synchronous/blocking** — §8.1's provider interface (submit → poll → download inside `generate()`) blocks the calling job slot for the generation's duration (≤10 min cap). This matches the queue design: `generate_ai` jobs occupy non-render slots, and long-poll state lives in the job row (progress/checkpoints in `generations.params`), not in an async callback surface. Webhook-driven async delivery is a v2 concern.
14. **Vendor cost propagation** — `GenResult.cost_usd` flows to `generations.vendor_cost_usd` (Decimal 10,4) summed across takes; providers that don't report cost (fal responses without pricing metadata) leave it NULL rather than writing a fabricated 0. StubProvider reports 0.0 (true cost).
